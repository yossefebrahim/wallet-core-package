# Phase 1 — M0: prove the whole pipeline on Ethereum

Back to [EXECUTION_PLAN.md](../EXECUTION_PLAN.md) · Status in [PROGRESS.md](../PROGRESS.md) · Plan 1.1: build-identity symbol, shared packaging harness (T1.19), session API with async close, key-less encoding, per-family adapter.

## Goal (PRD §18, M0, v1.2)

With threat model v0 and DECISION-11 to DECISION-14 recorded in Phase 0: pinned upstream tag and manifest; generated ffigen, protobuf, and registry; artifact fetch with checksum and the build-identity symbol; disposal contract; stable public coin facade; key-less request encoding; the §12 packaging evaluation on both options with the v1.2 checks; the §11.4 A-vs-B prototype; CI running the tests on an Android emulator and an iOS simulator. Signing may run same-isolate inside the session during the spike; signing duration is measured before the worker is built in Phase 2.

## Exit criteria (verbatim from PRD §18, v1.2)

On Android (emulator + device) and iOS (simulator + device), in **debug and release**: create wallet; import a known mnemonic; derive the expected Ethereum address; sign an EIP-1559 transfer and match a known vector **byte-for-byte**; invalid mnemonic / invalid address / invalid path each raise typed errors; explicit `dispose()`/`close()` paths exercised and leak tracker reports zero undisposed objects; a fresh consumer app installs cleanly from packaged (not path) dependencies with no manual native edits; the identity check passes and a mismatched manifest fails; DECISION-1 and DECISION-2 recorded with data.

Plan additions: DECISION-6 (minimum Flutter/Dart versions) and DECISION-14 (distribution contract, with T1.2 evidence) recorded at D1a; every generated directory passes `gen:check`; the public export passes `lint:public-api`; no public signature exposes the generated `CoinType`.

## Task notes

**T1.1 — Upstream pin and fetch.** `tools/upstream/fetch.dart` reads `upstream.tag` from the manifest, downloads the source archive for the tag (or accepts `--from <path>` when pre-fetched), resolves the commit sha and writes it to `upstream.commit` (or verifies it if already set), extracts to `third_party/wallet-core/`, computes deterministic hashes for `include/TrustWalletCore/`, `src/proto/`, and `registry.json` into `schemas.*`, and copies the upstream NOTICE/LICENSE text into `THIRD_PARTY_NOTICES.md`. Script `melos run upstream:fetch`. Acceptance: idempotent; `manifest:validate` green; hashes stable across two runs.

**T1.2 — Native artifacts.** Branches on DECISION-9. Mirror variant: the workflow downloads the upstream assets for the tag, re-lays them out as `android/<abi>/libTrustWalletCore.so` and `ios/TrustWalletCore.xcframework.zip`, builds a small companion library from `src/identity/wcf_build_info.c` (exports `wcf_build_info()` returning the upstream commit and artifact-set id) for every ABI and slice, computes sha256 and size, and attaches everything to a release of this repository named `native-<tag>-<n>`. Build variant: builds the pinned commit in upstream's Docker image or a pinned NDK/Xcode/cmake/rust set for Android `arm64-v8a` and `x86_64` (plus `armeabi-v7a` only if it will be tested) and an iOS device+simulator xcframework, linking `wcf_build_info` in; same upload. Either way: every 64-bit Android library is checked for 16 KB page alignment in the workflow and the check command is recorded; `libc++_shared.so` handling is recorded; a macOS host library is produced or located when possible so `test:native` runs on the development machine; the manifest `identity`, `artifacts`, and `toolchain` blocks are filled from the workflow output and committed by the orchestrator. Acceptance: static validation locally; the first green run happens once the human creates the remote.

**T1.3 — ffigen + inventory.** `ffigen.yaml` over `third_party/wallet-core/include/TrustWalletCore/*.h`. `tools/inventory/symbols.dart` parses every exported function and enum in the headers and the generated Dart, and writes `inventory.json` (`symbol → {in_headers, in_generated}`). `inventory:check` fails on any header symbol missing from the generated set. `gen:check` regenerates and fails on a diff. The ffigen version is pinned in the bindings pubspec and written to manifest `generators.ffigen`. Acceptance: zero missing symbols; `gen:check` and `inventory:check` green.

**T1.4 — Protobuf.** Pin `protoc_plugin` (record the version), generate every `src/proto/*.proto` into `lib/src/generated/proto/`, add the `protobuf` runtime dependency, write `generators.protoc` and `generators.protoc_gen_dart`. Also emit `lib/src/generated/proto/key_fields.json`: for every generated `SigningInput`-style message, the field names whose name contains `private_key` (the reviewed per-family key-field list of PRD §11.4 starts from this file). Acceptance: all proto files have generated classes; `Ethereum.SigningInput.privateKey` exists; `key_fields.json` lists Bitcoin's repeated `private_key` and Solana's three key fields; `gen:check` green.

**T1.5 — Registry transform.** `registry.json` → `enum CoinType` (id = upstream coin id) and `CoinInfo` (name, symbol, decimals, derivation paths, curve, public-key type, explorer templates, blockchain family, chain id where present). Unit test over a fixed sample; count equals the registry length. The output is bindings-internal; the public facade over it is T1.11's job.

**T1.6 — Memory contract implementation (internal handles).** `NativeResource` base implementing `Disposable`: native pointer, `NativeFinalizer` attached with the pointer as token and the wrapper as detach key, `dispose()` calls the upstream delete then detaches then marks; double dispose is a no-op; `checkNotDisposed()` throws `DisposedError`. `TWDataHandle` (fromBytes, copyBytes, length), `TWStringHandle` (fromString, toDartString), `withTWData`/`withTWString` helpers releasing in `finally`, `ResourceScope` disposing everything created inside it exception-safely, and a debug-only `LeakTracker` (registrations, finalized-without-dispose count, creation stack traces) compiled out of release builds. Tests run on the host with the real library (`test:native`) or, failing that, in `integration_test` on the simulator. Acceptance: every item 1–7 of PRD §11.2 has a named test; item 8 (proxy `Finalizer`) is T1.11's.

**T1.7 — Native loader.** `WalletCoreNative.load()` returns the `DynamicLibrary` per platform; `verifyIdentity()` calls `wcf_build_info()` and compares upstream commit and artifact-set id with the bundled manifest, and compares the release-set id embedded in the three packages; `NativeLoadError`, `ManifestMismatchError`; `symbolLookupAll(inventory)` as the health check. The library file is never hashed at runtime. `tool/fetch_artifacts.dart` downloads from the content-addressed release URL, verifies sha256, caches under `WCF_ARTIFACT_DIR` or `~/.cache/wallet_core_flutter/<tag>/`, supports a vendored offline mode, and fails loudly on mismatch. Acceptance: verification logic unit-tested with fake files and a fake identity function; a wrong sha and a wrong identity each fail with a clear message.

**T1.8 / T1.9 — Packaging evaluations.** Each executes PRD §12.2 steps 1–11 on the real artifacts through the T1.19 harness and writes the harness's data table: emulator x86_64, arm64 device, iOS simulator, iOS device; debug and release; `nm`/`objdump` symbol presence plus the runtime lookup test; sizes per ABI/slice and app-size delta; the minimum Flutter/Dart version needed; clean consumer install from packaged dependencies; wrong-checksum behavior; 16 KB alignment; `libc++_shared` conflict with the fixture plugin; iOS minimum target, archive linking, symbol visibility, duplicate symbols, privacy-API scan result. Option 1 uses `hook/build.dart` with `CodeAsset` and `DynamicLoadingBundled()`; Option 2 uses Gradle packaging of the `.so` files (bundling `libc++_shared`) and a podspec vendoring the xcframework. The orchestrator runs the device steps during review and pastes the results if the implementer's sandbox cannot. Both land on their eval branch only.

**T1.10 — Ethereum vectors.** Entries with `variant`: BIP-39 mnemonic → Ethereum address at `m/44'/60'/0'/0/0` (`n/a`); an EIP-1559 transfer signing input with expected raw bytes and hash (`eip1559`); invalid mnemonic; invalid address; invalid derivation path (`n/a`). Sources are upstream test files at the pinned commit (the brief supplies the sha) or a standard reference. `vectors:validate` green.

**T1.11 — SDK core.** Implements the interface sketches from T0.11. `WalletCore.initialize()` returns a session with the §14.3 states; in M0 the session runs an in-process executor that speaks the same message protocol the Phase 2 worker will (so the public API is already asynchronous and message-shaped). `wc.wallets.create/importMnemonic/importEntropy` return `Wallet` proxies with idempotent `Future<void> close()` and a Dart `Finalizer` fallback that posts `Dispose(ref)`; `wallet.account(coin, path)` returns an `Account` descriptor (coin, derivation path, address, public key) that owns nothing; the stable `Coin` facade (DECISION-11) with explicit network where upstream has only a derivation; `Mnemonic.validate` and word lists; `Address.parse/validate` via `TWAnyAddress` for every registry coin; the error hierarchy of PRD §10.2 v1.2; `wc.scope(...)`. The same-isolate `HDWallet` with synchronous `dispose()` is exported only from `advanced.dart`. Validation happens in Dart before native calls where feasible (S5). Acceptance: create with strength 128 and 256; import the known mnemonic and match the vector address; invalid inputs raise the typed errors; close during an in-flight derive waits then disposes; leak tracker reports zero after a scope; no `dart:ffi`, generated (including `CoinType`), or protobuf type in any public signature.

**T1.12 — EVM request, key-less encoder, Approach A.** `EvmTransactionRequest.transfer(...)` (immutable, validated, no key material). `families/evm/encode.dart` exposes `encodeKeylessInput(request)` producing the serialized `Ethereum.SigningInput` without a key and `parseSigningOutput(bytes)` producing `EvmSignResult` (encoded bytes, hash, v/r/s). `Signer.sign(request, keys)` with `KeyLocator.hdPath(walletRef, coin, path)`; `LocalSigner.sync` resolves the locator inside the same isolate, checks with the `key_fields.json` list that the key-less bytes contain no key field, injects the key, calls `TWAnySignerSign`, maps `SigningOutput.error` to `SigningError`, and overwrites its own `Uint8List` copies in `finally`. The decision doc counts the Dart-side copies of the key that remain. Acceptance: byte-for-byte match with the T1.10 vector; a request whose encoded bytes were tampered to include a key field is rejected before injection.

**T1.13 — Approach B.** A per-family native adapter for Ethereum, `wcf_sign_ethereum(keylessInput, privateKeyHandle)`, that appends the key field the descriptor names (checked by a test against `key_fields.json`), calls `TWAnySignerSign`, wipes its buffers, and returns the output; the Dart side is a `LocalSigner.adapter` behind the same interface; the same vector test passes; the decision doc records effort, build complexity under the packaging option chosen at D1a, review scope, and what generalizing to Bitcoin's repeated field and Solana's three fields would require. Lands on `eval/approach-b`.

**T1.14 — SignJSON probe.** Iterate the generated `CoinType.values` over `TWAnySignerSupportsJSON`; write the evidence table. Resolves the PRD's [UNVERIFIED] coverage question for DECISION-1.

**T1.15 — Public-API lint.** Resolve the exports of `wallet_core_flutter.dart` with `package:analyzer`, walk every public declaration's signature types, and fail if any type comes from `dart:ffi`, `package:ffi`, a `generated/` path (including `CoinType`), or `package:protobuf`, or holds a `Pointer` field. Wired as `lint:public-api` and in CI.

**T1.16 — Example and consumer check.** `example/` runs the M0 flow end to end and shows the leak-tracker report. `tools/consumer_check.sh` uses the T1.19 generator: creates a fresh app with `flutter create`, publishes the three packages to a local package repository (or consumes the `pub publish --dry-run` archives), adds the SDK as a hosted dependency, builds debug and release for both platforms, and runs the flow on the emulator and simulator; no path dependencies, no manual native edits.

**T1.17 — CI device jobs.** Fill the T0.2 placeholders: iOS simulator job and Android emulator job (for example `reactivecircus/android-emulator-runner`) running `test:ios` and `test:android`; artifact fetch with checksum; `gen:check`, `inventory:check`, `lint:public-api`, `vectors:validate`, `manifest:validate`; the S4 no-network runtime test (run the flow with networking disabled and assert no socket was opened; the implementer proposes the mechanism, the orchestrator reviews it) plus `runtime_deps_check.dart` failing if any of the three packages has a networking package as a runtime dependency; an identity-mismatch negative test (a manifest with a wrong artifact-set id must make `initialize()` throw `ManifestMismatchError`).

**T1.18 — Memory and lifecycle docs.** PRD §11.2 as implemented (real class names from T1.6), §11.3 "what we wipe / what we can't", the mnemonic import/export notes, and a lifecycle page: what `close()` does on a proxy, what `dispose()` does on an internal handle, the session states, and what happens after worker termination. README links both. None of the forbidden words.

**T1.19 — Packaging measurement harness.** Scripts under `tools/packaging_eval/` that both evaluations call: per-ABI/slice size and app-size delta; symbol presence against `inventory.json`; 16 KB alignment check for ELF segments and APK/AAB packaging; a fixture Flutter plugin bundling `libc++_shared.so` to detect conflicts; iOS archive link check, symbol visibility, duplicate symbols, minimum deployment target, and a required-reason API scan; a generator that stands up a local package repository (or uses `pub publish --dry-run` archives) so consumer apps depend on hosted, not path, packages; a writer that renders the results table both decision docs embed. Acceptance: each script runs against the T1.2 artifacts on this machine and prints the table; no evaluation-specific logic.

## D1a — Checkpoint debate brief outline

- **Agreed points:** both evaluations ran every step 1–11 of PRD §12.2 on the real artifacts through the same harness; the data tables exist; T1.2 produced the identity symbol for the chosen artifact source.
- **Contested points:** Option 1 vs Option 2 vs Option 1 with Option 2 fallback; the minimum Flutter/Dart versions each implies (DECISION-6); DECISION-14: exact pins and release set, retention promise and mirror cost, whether the companion identity library (mirror variant) is acceptable versus building from source.
- **Questions:** Does either option leave a symbol unresolved in release builds? How is `libc++_shared` handled in each, and does the fixture plugin conflict? Are all 64-bit Android artifacts 16 KB aligned under each option? What does a static-only xcframework mean for Option 1? Does a wrong checksum and a wrong identity each fail loudly on both platforms and both options? Which option costs consumers more setup?

## D1 — Phase debate brief outline

- **Agreed points:** each M0 exit criterion with evidence (test names, device results, example app, consumer-check log from packaged dependencies, identity-mismatch negative test, decision docs).
- **Contested points:** DECISION-1: Approach A vs B vs "A now, B later" using T1.12 copy counts, T1.13 effort and generalization notes, and T1.14 coverage; ratification of DECISION-2, DECISION-6, DECISION-14.
- **Questions:** For each item 1–8 of PRD §11.2, satisfied / not / unprovable, citing `packages/*_bindings/lib/src/memory/` and the proxy `Finalizer` in the SDK. Can any public object free a native pointer synchronously? Does `close()` during an in-flight operation behave as §14.3 says? Is the key-field check applied before every injection? Is any validation (S5) missing before a native call? Is any generated file hand-edited? Does the public export leak any forbidden type, including the generated `CoinType`? Spot-check two vectors' provenance against the pinned commit. Does the README or any doc use a forbidden word?
