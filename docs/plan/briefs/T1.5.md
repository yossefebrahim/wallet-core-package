  2. The transform reads `registry.json` and writes two files into `packages/wallet_core_flutter_bindings/lib/src/generated/registry/`:
     - `coin_type.dart` — `enum CoinType` with one member per registry entry. **Dart enums cannot carry an arbitrary integer as their index**, so each member takes the upstream coin id as a field: `bitcoin(0)`, `ethereum(60)`, and so on, with a `final int coinId;` and a `static CoinType? fromCoinId(int id)` lookup. The upstream `coinId` is the value that crosses the FFI boundary; the enum's own `index` never does.
     - `coin_info.dart` — a `CoinInfo` type and one constant entry per coin, carrying: `name`, `symbol`, `decimals`, the derivation entries (each with its name, path, and xpub/xprv prefixes where present), `curve`, `publicKeyType`, `blockchain` (the family), the explorer templates (`url`, `txPath`, `accountPath`), and `chainId` **where present** — 99 of the 167 entries have one, so it is nullable. Also carry `deprecated` (2 entries are), and `hrp` where present. Keep the shape close to upstream's field names so a reader can check it against `registry.json` by eye.
  3. **Identifier safety.** Two upstream ids are not valid lower-camel Dart identifiers as written: `Nebl` and `internet_computer`. Normalise deterministically (`Nebl` → `nebl`, `internet_computer` → `internetComputer`), apply the same rule to every id rather than special-casing those two, and **fail the transform** if normalisation ever produces a duplicate or a Dart reserved word. A silent collision here would silently mis-map a coin.
